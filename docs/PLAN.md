# 프로젝트 시스템 운영비 정산 웹앱 — 기획안 및 Claude Code 설계서

Oct 9, 2026 · @AX플랫폼운영팀

## PART 1. 기획안

팀원이 개인식 법인카드로 지출한 내역을 PM이 엑셀에 수기로 취합해 월 1회 상신하는 현재 프로세스를, 입력·정산·상신이 한곳에서 이루어지는 웹앱으로 전환한다. 기존 상신 양식(엑셀)은 그대로 자동 출력해 본사 프로세스 변경 없이 도입한다.

### 1. 배경 및 문제 정의

| # | 현재 문제 | 엑셀 근거 | 웹앱 해결 방향 |
| --- | --- | --- | --- |
| 1 | 총괄현황 시트가 `#REF!` 오류로 집계 불가 | 총괄현황 시트 | DB 집계로 정합성 보장 |
| 2 | 분류 명칭이 월마다 다름 (프로젝트운영 ↔ PM운영비/복리후생비) | 1월 vs 2월 시트 | 분류 마스터와 회계계정을 분리 관리 |
| 3 | 항목 오분류 (도서·구독료가 PM운영비로 기록) | 2월 시트 | 항목 선택 강제 + 키워드 추천 |
| 4 | 팀원 추가 시 정산표 수동 수정 | 2월 신규 결제자 | 결제자 마스터 기반 자동 집계 |
| 5 | 예산 대비 집행률을 수동 확인 | 작성금지 시트 | 대시보드 실시간 표시 |
| 6 | 상신 이력·승인 상태 추적 불가 | 없음 | 월 마감/상신 워크플로우 |
| 7 | 날짜가 시리얼 숫자로 저장 | 전 시트 | 표준 Date 타입 |

### 2. 목표

- PM의 월 취합·정리 시간을 1/3 이하로 단축
- 팀원이 모바일에서 지출 즉시 입력
- 기존 상신 양식(엑셀)을 그대로 자동 출력
- 영수증 첨부는 범위에서 제외(2026-10-14 결정) — 증빙은 법인카드 내역으로 갈음

### 3. 사용자 및 역할

| 역할 | 주요 행위 |
| --- | --- |
| 팀원(Member) | 본인 지출 입력/수정(개인식법인카드, PM이 노출한 항목만), 본인 정산 조회, 출입증 사용분 조회·업무 사용 표시(표시 없음 = 본인 부담) |
| 프로젝트 PM(Manager) | 자기 프로젝트의 전체 조회·수정, 대신 입력, 월 마감·상신·마감 해제, 엑셀 출력, 출입증 정산(올리기·결정·확정), PM 설정(팀원·팀원 지출 항목·협력 인력·출입증 사용), 현재 팀원 임시 비밀번호 발급 |
| 재무 승인(HQ) | 전 프로젝트 조회, 본사 집행내역 입력(본사지출), 상신 승인/반려/승인 취소, 예산(프로젝트 운영비) 편집, 분류·항목 기준 정보, 프로젝트 등록·종료·PM 지정, 출입증 확정 취소 |
| 시스템 관리자(Admin) | 사용자·조직·접속 기록 관리, 프로젝트 정보·PM 지정·변경계약. 프로젝트 데이터(지출·마감·출입증)는 조회 전용 |

- 다른 프로젝트에서는 PM 권한자도 팀원으로 동작한다. 상위 프로젝트 PM·조직장은 하위 프로젝트를 조회 전용으로 본다(팀원별 정산·엑셀·출입증 개인 내역 제외).
- 화면 접근은 `lib/page-access.ts`, 메뉴는 `components/Nav.tsx`, API 역할 검사는 `lib/access.ts`로 같은 기준을 쓴다.

### 4. 핵심 기능 (MVP) — 모두 구현됨

1. 프로젝트/예산 관리 — 분류·항목별 단가×기간=계획금액 등록 (엑셀 `작성금지` 시트 대응)
2. 지출 입력 — 날짜, 금액, 결제방법, 분류, 항목, 세부내역, 대상인원, 참석자 (+ 규정 점검·소명)
3. 팀 현황(월별 지출 내역) — 월 시트와 동일한 내역 + 개인집행/본사집행 구분
4. 팀원별 정산 자동 집계 — 결제자별 합계, 공용법인카드, 본사, 총계 검증
5. 예산 대비 집행 대시보드 — 항목별 계획/지출/잔액, 월별 추이
6. 월 마감 및 상신 — 작성중 → 마감 → 상신 → 승인/반려 (+ 승인 취소·마감 해제, 상신본·승인본 스냅샷)
7. 엑셀 출력 — 기존 양식(총괄현황/작성금지/월별 시트) 그대로 생성
8. 출입증 정산 — 업체 내역 올리기 → 팀원 연결 → 회사 부담 결정 → 월 확정 (MVP 이후 추가, §6)

### 5. 2차 범위 (Post-MVP)

- 복수 프로젝트 분담률(데이터시트의 분담률1/2) 기반 원가 배분 — 미착수
- Slack/메신저 알림 (미입력 리마인드, 상신 결과) — 메신저 연동은 보류, 앱 내 알림(상신·승인·반려·승인 취소, 입력·소명 요청, 출입증 확인·확정)은 구현 완료(2026-10-14 결정, `lib/notifications.ts`). 웹 푸시: 알림 화면에서 기기별로 켜면 같은 알림을 휴대폰·PC 알림으로도 받는다(2026-10-16, `lib/push-server.ts`·`public/sw.js`, 키는 VAPID_PUBLIC_KEY·VAPID_PRIVATE_KEY, 아이폰은 홈 화면에 추가한 앱에서만)
- 회계계정 자동 매핑 (프로젝트운영 → 복리후생비/여비교통비 등) — 항목별 `Item.accountCode`와 계정 확인 점검(ACCOUNT_CHECK)까지 구현, 계정 마스터·자동 매핑은 미착수(REVIEW P1-15)

### 6. 업무 흐름 (`lib/closing.ts`·`lib/pass-statement.ts`·`lib/snapshot.ts` 기준)

1. 팀원: 지출 발생 시 앱에서 즉시 입력. 규정 점검(1인당·1건 한도, 예산 초과, 중복, 출입증 중복, 계정 확인)에 걸리면 소명 사유를 적어야 저장된다. 주말·심야 사용은 점검하지 않는다(2026-10-15 확정). PM은 앱 내 알림으로 입력·소명을 요청할 수 있다.
2. 출입증(쓰는 프로젝트만): PM이 업체 월 내역(엑셀·CSV)을 올린다 → 업체 파일의 이름을 팀원에 연결(다음 달부터 자동) → 팀원이 **업무 사용** 표시(표시 없음 = 본인 부담, 따로 확인하지 않음) → PM이 회사 부담(항목 지정)·본인 부담 결정 → **월 확정**(OPEN → CONFIRMED). 확정은 줄을 바꾸지 않고, 결정이 비어 있는 줄은 읽을 때 본인 부담(출처 "기본")으로 채운다(`applyConfirmedDefaults`). 확정 취소는 PM·재무 승인 담당. 회사 부담 줄은 예산 항목에 연결되면 본사 집행내역·예산 집행에 들어간다.
3. PM "월 마감" (작성중·반려 → 마감): 정산 검증 FALSE(팀원별 + 공용 + 본사 ≠ 총합계)면 차단. 마감 이상인 달의 지출은 등록·수정·삭제 403. 아직 시작하지 않은 달은 마감·상신할 수 없다.
4. PM "상신" (마감 → 상신): 상신 가드 — 출입증 확정 전·내역 없음, 회사 부담 줄의 예산 항목 미연결, 소명 없는 점검 건, 서브 프로젝트 미처리는 **사유(10~300자)를 적으면 그대로 상신**할 수 있고, 검증 불일치만 사유로도 넘길 수 없다(`submitBlockers`·`submitOverrideProblem`). 마감 뒤 총합계가 달라졌으면 다시 마감하라고 안내. 상신 시 상신본 엑셀 스냅샷(`ClosingSnapshot` SUBMIT)을 저장하고 재무 승인 담당에게 알림.
5. 재무 승인 담당: 승인(상신 → 승인, 결재 문서번호 선택 입력, 승인본 스냅샷 APPROVE 저장) 또는 반려(상신 → 반려, 사유 필수) → PM에게 알림. 승인된 달의 엑셀은 다시 만들지 않고 승인본을 내려준다. 반려되면 PM이 수정 후 다시 마감·상신한다.
6. 되돌리기: **승인 취소**(승인 → 반려, 재무 승인 담당, 사유 필수) · **마감 해제**(마감·반려 → 작성중, PM, 사유 필수 — 2026-10-15 결정, 감사 기록에 남김). 상신·승인된 달은 PM이 풀 수 없다. 서브 프로젝트는 메인 PM이 한 엑셀로 함께 상신한다.

### 7. 성공 지표

월 마감 소요시간, 상신 반려율, 항목 오분류 건수, 팀원 입력 지연일수 — 집계 화면·정의는 미구현(REVIEW P1-13)

## PART 2. 설계서 (Claude Code 활용용)

Next.js + Prisma 단일 저장소로 구현하고, 정산 계산 로직은 순수함수로 분리해 테스트한다. 엑셀의 각 시트는 아래 데이터 모델의 테이블 하나에 대응한다.

### 1. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js 15 (App Router) + TypeScript | 풀스택 단일 저장소, Claude Code 생산성 높음 |
| UI | Tailwind CSS 공통 클래스(`app/globals.css`) | 표·폼 중심 화면에 적합 (shadcn/ui는 쓰지 않음) |
| DB | PostgreSQL (개발: SQLite) + Prisma | 스키마 관리 용이. enum은 SQLite 호환을 위해 String 컬럼 + `lib/types.ts` 상수 |
| 인증 | HMAC 서명 쿠키 + scrypt 비밀번호(`lib/session.ts`), 추후 SSO | 역할 기반 접근 (NextAuth 대신) |
| 엑셀 | exceljs | 기존 양식 재현 |
| 파일 | 출입증 업체 내역 엑셀·CSV (저장하지 않고 읽어서 줄로 보관) | 영수증 첨부 없음 — 파일 스토리지 불필요 |
| 테스트 | Vitest (Playwright E2E는 미구현) | 정산 계산 단위 테스트 필수 |

### 2. 데이터 모델

현재 모델은 `prisma/schema.prisma` 참조(모델별 주석 포함). 규칙: 금액은 원 단위 정수, 집계 키는 `yearMonth`("YYYY-MM"), 상태·결제방법 등 enum 값은 String 컬럼에 `lib/types.ts` 상수로 저장, 분류·항목은 마스터 참조.

### 3. 핵심 계산 규칙 (엑셀 수식 → 코드)

| 규칙 | 정의 |
| --- | --- |
| 월 총합계 | 개인 집행내역 합 + 본사 집행내역 합 |
| 팀원별 정산금액 | payMethod=PERSONAL\_CARD AND isHq=false 를 payer별 SUM |
| 공용법인카드 | payMethod=SHARED\_CARD 합 |
| 본사 | isHq=true 합 (확정된 출입증 회사 부담 줄 포함 — 엑셀 본사 집행내역에 함께 기록) |
| 검증(TRUE) | 팀원별 합 + 공용 + 본사 == 월 총합계 |
| 예산 지출 | item별 누적 SUM(amount) |
| 잔액 | planned − 지출 |
| 월 컬럼 | yearMonth별 item SUM → 작성금지 시트 월 컬럼 |
| 출입증 결정 기본값 | 확정(CONFIRMED)된 출입증 내역에서 decision이 비어 있는 줄 = 본인 부담(DEDUCT, 출처 "기본"). 확정 때 줄을 바꾸지 않고 읽을 때 채운다(`applyConfirmedDefaults`) — 확정 취소하면 자동으로 다시 미결정 |

### 4. API 설계

```text
POST   /api/projects                         프로젝트 생성
GET    /api/projects/:id/budget              예산 라인 목록
PUT    /api/projects/:id/budget              예산 일괄 저장
GET    /api/projects/:id/expenses?ym=2026-02 월별 지출 목록
POST   /api/projects/:id/expenses            지출 등록
PATCH  /api/expenses/:id                     수정 (마감 전만 허용)
DELETE /api/expenses/:id
GET    /api/projects/:id/settlement?ym=      팀원별 정산 집계
GET    /api/projects/:id/dashboard           예산 대비 집행 현황
POST   /api/projects/:id/closings/:ym/:action 월 마감·마감 해제·상신 (close | reopen | submit, PM)
GET    /api/projects/:id/closings/:ym/preflight 상신 전 미완료 항목
POST   /api/closings/:id/review              승인/반려/승인 취소 (재무 승인)
GET    /api/closings/:id/snapshots/:sid      상신본·승인본 내려받기
GET    /api/projects/:id/export?ym=          엑셀 다운로드
GET    /api/master/categories                분류/항목 마스터
```

출입증·알림·변경계약·관리자 API 등 전체 목록은 `app/api/**` 참조.

### 6. 엑셀 출력 사양

- 시트 구성: `총괄현황`, `프로젝트 운영비`, `{YY.M월}` × 12, `유효성검사`
- 월 시트 컬럼 순서: 결제자 | 날짜 | 금액 | 결제방법 | 분류 | 항목 | 세부내역 | 대상인원 | 참석자
- 오른쪽 블록: 팀원별 정산금액(결제자/금액), 공용법인카드, 본사, 계, 검증
- 날짜는 `yyyy-mm-dd` 서식의 실제 Date 셀로 출력 (시리얼 숫자 금지)

### 7. 비기능 요구사항

- 마감 이후 지출 수정 금지(PM이 사유를 적고 마감 해제한 뒤에만 가능; 상신·승인된 달은 재무 승인 담당의 반려·승인 취소가 먼저), 모든 변경은 감사 기록(`AuditLog`)
- 상신본·승인본 엑셀은 스냅샷으로 보관(SHA-256), 승인된 달의 예산 변경은 사유 필수
- 출입증 업체 내역 파일 10MB 제한, 프로젝트 외 사용자 접근 차단
- 참석자·거래처명은 개인정보 → 최소 수집, 역할별 열람 제한
